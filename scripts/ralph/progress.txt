## Codebase Patterns
- Code lives in `src/config-gen/` (NOT `packages/generator/` as PRD says — adapt paths accordingly)
- Tests use Vitest with `import { describe, it, expect } from 'vitest'`
- Test files are in `__tests__/` directories adjacent to source
- Integration test fixtures in `src/config-gen/__tests__/integration/fixtures/`
- Integration test expected outputs in `src/config-gen/__tests__/integration/expected/`
- Root exports from `src/index.ts` re-export from `src/config-gen/index.ts`
- Typecheck: `npx tsc --noEmit --target es2022 --module nodenext --moduleResolution nodenext --strict --skipLibCheck --esModuleInterop <files>`
- Run tests: `npx vitest run`
- The tsconfig extends `@docs/configs/tsconfig/base.json` which doesn't exist in this repo — use explicit tsc flags instead
- CLI is at `src/config-gen/cli.ts`
- `@types/node` needed for Node.js type definitions (was added as devDep)
- New renderer is in `src/config-gen/renderers/cfg-renderer.ts` — use `renderXrpldCfg(config)` to render XrpldInput to cfg string
- Old template-based generator (generators/xrpld.ts, template.ts) and legacy `getXrpldDefaults()` have been deleted
- Full generator pipeline: `resolveXrpldConfig(input)` → `validateXrpldConfig(resolved)` → `renderXrpldCfg(resolved)` → `generateValidatorsTxt(resolved)`
- Use `generateXrpldConfig(input)` for the all-in-one entry point returning `{ config, validatorsTxt, warnings }`
- `XrpldPortConfig.protocol` is required — always include when defining ports
- VL config is nested under `vl` property in XrpldInput (validator_list_sites, validator_list_keys), not top-level
- `validateXrpldConfig(config: XrpldInput)` is in `validation.ts` — returns `{ errors, warnings }` with typed `ValidationEntry[]`
- Default resolved configs generate warnings (no validator_token) — tests should not assert 0 warnings on defaults
- Old flat env-based `validateXrpldInputs` is removed — all validation now uses typed `XrpldInput`
- CFG parser is in `src/config-gen/parsers/cfg-parser.ts` — use `parseCfgFile(content)` to parse cfg string to XrpldInput
- Text file parser is in `src/config-gen/parsers/env-parser.ts` — use `parseTextFile(content)` to parse SCREAMING_SNAKE_CASE text to `Partial<XrpldInput>`
- JSON parser now returns `Partial<XrpldInput>` directly (nested structure, no flattening)
- Example cfg file is at `src/xrpld/etc/xrpld-example.cfg`
- CLI `run()` takes `CliArgs` only (no env param) — uses file-based inputs exclusively
- CLI `--output` is a directory path — writes xrpld.cfg + validators.txt (or xrpld.json in parse mode)
