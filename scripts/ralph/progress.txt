## Codebase Patterns
- Code lives in `packages/generator/` (monorepo package)
- Tests use Vitest with `import { describe, it, expect } from 'vitest'`
- Test files are in `packages/generator/tests/` mirroring `src/` structure
- Run tests: `cd packages/generator && npx vitest run`
- Typecheck: `npx tsc --noEmit -p packages/generator/tsconfig.json` (from repo root, not package dir)
- Full generator pipeline: `resolveXrpldConfig(input)` → `validateXrpldConfig(resolved)` → `renderXrpldCfg(resolved)` → `generateValidatorsTxt(resolved)`
- Use `generateXrpldConfig(input)` for the all-in-one entry point returning `{ config, validatorsTxt, warnings }`
- `validateXrpldConfig(config: XrpldInput)` is in `validation.ts` — returns `{ errors, warnings }` with typed `ValidationEntry[]`
- CLI is at `packages/cli/`
- Preset defaults pattern: export `VALID_*` ReadonlySet + `get*Defaults()` function + `*_MAP` record
- Merge order in resolveXrpldConfig: common < size < role < verbosity < network < user
- When changing defaults, regenerate expected .cfg files
- Invalid preset values crash `resolveXrpldConfig` — test invalid presets by constructing config with spread, not via `makeConfig()`
